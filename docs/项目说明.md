# AI Daily News 项目说明

本文档根据当前仓库代码整理，介绍项目用途、模块结构、运行流程和配置方式。项目入口和主要实现位于 `src/`，默认配置位于 `config/`，日报生成提示词位于 `prompts/`。

## 1. 项目用途

AI Daily News 是一个自托管的 AI 行业资讯日报生成器。它从 RSS 和可选的 X（Twitter）账号收集近期内容，对内容评分、去重和预分类，再调用 OpenAI 兼容的聊天模型生成 Markdown 日报。日报默认保存到本地，也可以创建微信公众号草稿或发送到 Telegram；此外可以把日报转换成播客音频。

它是一个按计划启动的批处理脚本，不是常驻 Web 服务。仓库提供 GitHub Actions 定时工作流和 Docker 配置，也可以由本地定时任务或其他调度器调用。

## 2. 架构概览

```text
调度器 / 手动命令
        │
        ▼
src/handler.py（流程编排）
        ├── collectors/rss.py       读取 config/feeds.yaml，采集 RSS
        ├── collectors/twitter.py   可选采集 config/x_accounts.yaml 中的账号
        ├── processor/preprocessor.py 评分、去重、分类、排序和低分过滤
        ├── processor/generator.py  读取 prompts/ 并调用 LLM
        ├── processor/content_filter.py  可选敏感词检查和行过滤
        ├── audio/podcast.py        可选生成播客 MP3
        └── publisher/              Markdown、微信公众号、Telegram 发布器
```

## 3. 一次运行如何工作

入口命令是 `python src/handler.py [小时数]`，小时数默认为 24。程序使用当前机器的本地日期作为日报日期和输出文件名中的日期。

1. **采集 RSS**：逐个读取 `config/feeds.yaml` 中的 feed，解析发布日期，只保留在回看窗口内的条目；没有发布日期的条目也会保留。单个 RSS 源失败会记录错误并继续处理其他源。
2. **采集 X（可选）**：只有 `X_AUTH_TOKEN` 和 `X_CT0` 都存在时才启用。程序逐个读取账号时间线，每个账号最多取 10 条，按时间窗口筛选；遇到 HTTP 429 会等待后重试一次。设置 `PROXY_URL` 可为 X 客户端指定代理。
3. **保存原始数据**：有采集结果时写入 `data/raw-YYYY-MM-DD.json`。若没有任何条目，流程会提前结束，不调用 LLM，也不产生日报。
4. **评分、去重与筛选**：评分后按 URL、标题相似度和 X 摘要相似度合并重复项，添加分类建议和多源数量，按分数降序排列，最后移除分数低于 5 的条目。处理结果写入 `data/processed-YYYY-MM-DD.json`。
5. **生成日报**：调用配置的聊天模型，把处理后的 JSON 和中文或英文用户提示词发给模型。默认语言为中文。
6. **可选内容过滤**：`ENABLE_CONTENT_FILTER` 非空时检查模型生成的全文；命中词表后，删除包含敏感词的整行，并将命中词信息传给支持该参数的发布器。该过滤器是简单的字符串匹配，不是语义审核。
7. **可选生成音频**：除非设置了非空的 `DISABLE_AUDIO`，程序会尝试通过 Podcastfy + Edge TTS 生成双人播客 MP3，并保存为 `data/audio-YYYY-MM-DD.mp3`。音频失败会被捕获，后续发布仍会继续。
8. **发布**：默认 Markdown 发布器始终启用，写入 `data/digest-YYYY-MM-DD.md`。配置微信或 Telegram 凭证后，相应发布器也会自动启用。`PUBLISHERS` 非空时仅在指定名称中选择已配置的发布器。

注意：配置开关按“是否为空”判断，因此 `DISABLE_AUDIO=0` 仍会禁用音频，`ENABLE_CONTENT_FILTER=0` 仍会启用过滤。要关闭它们请留空或移除变量。

## 4. 评分和去重规则

- RSS 条目基础分为 `15 × 时间衰减`。
- X 条目互动分为 `3×log2(点赞数+1) + 4×log2(转推数+1) + 2×log2(回复数+1)`，再乘账号权重和时间衰减。`weight: high` 的账号权重为 3，其他权重为 1。
- 时间衰减的半衰期是 24 小时；时间无法解析的条目使用 0.5 衰减值。
- 去重依次采用精确 URL、标题相似度不低于 0.65、同为 X 内容时摘要相似度不低于 0.8。合并条目会记录 `related_sources`，并在预处理后计算 `source_count`。
- 预分类由标题和摘要中的关键词匹配得到“要闻 / 产品 / 观点 / 其他”，作为提示字段交给 LLM；日报的最终编排由提示词指导模型完成。
- 低于 5 分的条目会在 LLM 调用之前删除。

## 5. 配置说明

从 `.env.example` 复制出 `.env`，至少填写 LLM 凭证：

```bash
cp .env.example .env
```

| 变量 | 用途 | 默认或说明 |
|---|---|---|
| `LLM_API_KEY` | LLM API 密钥 | 必填 |
| `LLM_BASE_URL` | OpenAI 兼容 API 地址 | 默认 `https://api.moonshot.cn/v1` |
| `LLM_MODEL` | 模型名 | 默认 `moonshot-v1-32k` |
| `DIGEST_LANG` | 日报语言 | `zh` 或 `en`，默认 `zh` |
| `X_AUTH_TOKEN`、`X_CT0` | X 登录 cookies | 两者都设置才采集 X |
| `PROXY_URL` | X 请求代理 | 可选 |
| `PUBLISHERS` | 限定发布器 | 逗号分隔，如 `markdown,telegram`；空值表示运行所有已配置发布器 |
| `WECHAT_APP_ID`、`WECHAT_APP_SECRET` | 微信公众号凭证 | 两者都设置后创建草稿，不会自动群发 |
| `WECHAT_API_BASE` | 微信 API 基地址覆盖项 | 可选，代码主要用于访问 token 接口 |
| `TELEGRAM_BOT_TOKEN`、`TELEGRAM_CHAT_ID` | Telegram 凭证和目标 | 两者都设置后启用 |
| `ENABLE_CONTENT_FILTER` | 启用敏感词过滤 | 非空即启用 |
| `DISABLE_AUDIO` | 禁止生成音频 | 非空即禁用 |
| `SERVERCHAN_KEY` | 微信草稿完成后的 Server 酱通知 | 可选 |

信源直接编辑 `config/feeds.yaml` 和 `config/x_accounts.yaml`。X 账号的 `name`、`bio` 会进入采集数据，供日报提示词在观点板块中标注作者。

## 6. 运行方式

### 本地运行

```bash
pip install -r requirements.txt
cp .env.example .env  # 填写 LLM_API_KEY
python src/handler.py 24
```

命令参数是回看小时数，例如 `48` 表示筛选最近 48 小时内容。

### Docker Compose

```bash
cp .env.example .env  # 填写配置
docker compose up --build
```

容器默认运行 24 小时窗口。Compose 将宿主机 `data/`、`config/`、`prompts/` 映射到容器；`.env` 通过 `env_file` 注入。

### GitHub Actions

`.github/workflows/daily.yml` 配置为每天 UTC 00:00 运行，也支持手动触发。将密钥放在仓库 Secrets，将非敏感选项放在 Variables。当前工作流会在 runner 上运行脚本，但没有配置上传 `data/` 为 artifact 或提交回仓库，因此本地产物不会自动长期保存；已启用的外部发布器仍会收到内容。

## 7. 发布器如何扩展

发布器在 `src/publisher/` 中实现以下约定：

```python
NAME = "my_publisher"

def is_configured() -> bool:
    ...

def publish(digest_md, date_str, **kwargs) -> str:
    ...
```

然后将模块导入并加入 `src/publisher/__init__.py` 的 `ALL_PUBLISHERS`。主流程会把 `audio_path` 和 `filtered_info` 作为关键字参数传给每个发布器；发布器异常会单独记录，不会阻止其他发布器继续执行。

## 8. 当前实现边界

- Gmail newsletter 配置目前只是 `config/feeds.yaml` 中的预留说明，没有对应采集代码。
- 没有采集结果时程序直接结束，不会生成“空日报”。
- GitHub Actions 当前不归档本地 JSON、Markdown 或 MP3 文件。
- 微信发布器创建公众号草稿，需在公众号后台手动发布；Telegram 将长文本拆分为多条消息，并在音频存在时另发音频。
- 项目依赖外部 RSS、X、LLM、微信/Telegram API 和 Edge TTS 服务，运行结果受网络和这些服务可用性影响。
