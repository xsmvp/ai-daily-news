# 2026-11-03

## 修复 X/Twitter 采集（twikit 与 X 接口双重失效）
- 报错链：`ValueError: Unknown scheme for proxy URL URL('')` → 因为 .env 里 `PROXY_URL=` 空串被当成有效值传给 httpx。
  同类问题此前出现在 ENABLE_ZH_SOURCES：**空字符串必须等同未设置**，已统一用 `_env()` 归一化（strip 后为空即 None），PROXY_URL 缺 scheme 时补 `http://`。
- 第二层：`Couldn't get KEY_BYTE indices`。X 把 web 分包清单从 `"ondemand.s":"<hash>"` 改成两张表 `{id:"ondemand.s"}` + `{id:"<16位hash>"}`，twikit 仍按旧格式找哈希。新增 `src/collectors/twikit_patch.py` monkeypatch `ClientTransaction.get_indices`，兼容新旧两种格式；实测分包 `ondemand.s.<hash>a.js` 仍在，索引模式不变。
- 第三层：`KeyError: 'urls'`。X 去掉了 `legacy.entities.description.urls`，twikit 的 `User.__init__` 直接下标取值。
  结论：twikit 模型层已整体失效（2.3.3 是最后一版，2025-02，两年未更新），改为**只用它生成签名/cookie（client.gql），GraphQL JSON 自己解析**，彻底绕开 User/Tweet 对象。
- requirements.txt 锁定 `twikit==2.3.3`（补丁依赖其内部符号，升级需复核）。
- 新增 `scripts/collect_x.py`（--handle/--all/--hours/--json），不花 LLM token 验证；实测 30 账号 24h 命中 17 个、43 条推文。
- 429 现象：连续跑两轮 30 账号会触发 rate limit，每命中一次等待 60s。日常一天一次不受影响。

## 接入 X 后暴露的排序失衡（已修）
- 互动量无上限：一条 5 万赞推文约 117 分，远超 tier1 RSS 的 25 分，「HBD SRK!」这种祝福语排第一。
- 修复：`TWITTER_SCORE_CAP = 30`（engagement 加权后封顶），使强推文与头条新闻同档；新增 `max_type_ratio: {twitter: 0.3}` 类型配额（每个 @handle 算独立 source，max_per_source 拦不住 30 个账号）。
- prompt 两侧同步说明：**推文的 score 只在推文内部可比**，不得因分数高进「今日要闻」，除非当事人发的是一手消息。
- 效果：输入 138 条 → 输出 88 条（zh 34 / en 54，twitter 27 条占 30%）；要闻恢复新闻主导，Levie 发布 Trajectory 平台这类一手消息被推特与 TechCrunch 合并收录。
