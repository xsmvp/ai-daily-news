## git push 认证失败排查
- 现象：push 到 origin (https://github.com/xsmvp/ai-daily-news.git) 报 401 Invalid username or token。
- 根因：credential.helper=osxkeychain（来自 Xcode 系统级 gitconfig），但钥匙串中无 github.com 的 internet password 条目；~/.gitconfig 的 [github] token 不参与 HTTPS 认证，git 实际以密码方式提交被 GitHub 拒绝。
- 结论：SSH 通道可用（ssh -T git@github.com 返回 Hi xsmvp；git push --dry-run 走 SSH 成功）。建议 remote 改为 SSH。
- 附带发现：~/.gitconfig 中有明文 PAT（仍有效），建议改用钥匙串或 SSH；工作区 .env.example 处于未提交删除状态。

## 新增国内 AI 信源检索
- 需求：日报原本只有海外 RSS + X，加入国内站点。
- 实测结论（逐站探测 RSS 可用性，详见 docs/zh-sources.md）：原生可用 13 个（量子位/雷锋网/极客公园/InfoQ中文/爱范儿/钛媒体/IT之家/开源中国/掘金/Solidot/Qwen官方博客等）；36氪、虎嗅只能用 RSSHub 公有镜像 rsshub.rssforever.com（官方 feed 已废/被 WAF 拦）；机器之心、新智元、界面、智东西、澎湃(feedx 已停更) 不可用。
- 设计决策：配置独立（config/feeds_zh.yaml）、采集器复用 collect_rss，不新写 collector。理由：tier 分级评分、strict 关键词过滤、来源配额三个机制必须在配置层表达。
- 关键实现点：
  - collect_rss 新增 config_path 参数，向后兼容；新增 tier/lang/filter_mode/filter_scope/max_items/enabled/summary_chars 可选字段。
  - ASCII 关键词必须按词边界匹配，否则 "AI" 命中 "email"/"said"。
  - filter_scope 默认 title：按摘要判定会让融资、生物医药稿因顺带提 AI 而混入。
  - preprocessor：base_score 由采集层算好写入 item；中文标题去重阈值 0.8、跨语言跳过（SequenceMatcher 对中文语义重复无效）；新增 max_per_source 配额与 max_total 截断。
  - 开关 ENABLE_ZH_SOURCES（.env + daily.yml 的 vars）。
- 效果：输入规模 39 条/2.3万字符 → 56 条/3.5万字符（未加配额与摘要截断时曾达 103 条/8.4万字符，LLM 会超窗）。实测一次生成 prompt=18950 tokens，正常输出。
- 教训：_collect_zh_if_enabled 关闭时最初返回 `[]` 给 limits，下游 .get() 会 AttributeError，已改 `{}`。
